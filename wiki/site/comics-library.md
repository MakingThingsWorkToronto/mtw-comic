## Where comic page art lives

Studio shows a scene's page art only when all three links of this chain exist. Generating a picture is not the end of the job.

| Link | Path | Who reads it |
|---|---|---|
| Master (canonical, registered) | `wiki/image-library/assets/scenes/comic-b/{pages,layers/<scene>/live-vN,models,…}/<stem>[-vN].png` | Studio Images (`/m/images`); the hooks' "has a library master" lookup |
| Delivery copies | `site/public/comic/<story>/[<folder>/]<stem>-1600.{webp,avif}`, and layer PNGs beside them | The reader; Studio Comics serves the `-1600` WebP |
| Story binding | `scenes[].art` (and `layers`) in `site/src/data/comic-stories/<story>.ts`, as `/comic/<story>/[<folder>/]<stem>` | The reader; Studio Comics reads the story file directly and re-reads it when it changes |

- Copies stop at the master's own width (Matt, 2026-10-11). Masters are about 1586 px wide, so the one width is 1600 (`page-constants.json` `artWidths`). A master narrower than 1600 fills the `-1600` file at its own width, never enlarged; the reader asks for that one name. No 2400/3200 copies: they were upscales with no extra detail. The 400 that existed are archived under `C:/MTW-archive/comic-upscales-20261011/` with a sha256 manifest.
- Name delivery copies after their master's stem: `<stem>-<width>.<ext>`. A copy named any other way has no master in the hooks' eyes and blocks the session.
- Subfolders such as `live-20261010/` are fine. Studio and the hooks accept any depth under `/comic/<story>/` (fixed 2026-10-11; before that, Studio showed "no art" for most of issues 2 and 4).
- A new version means a new master file (`-vN+1`), registered, and new delivery copies. Then point the story's `art` at the new stem. Studio shows the old art until the story file changes, and shows "no art" while the `-1600.webp` is missing.
- Codex image output (`~/.codex/generated_images/`) is transport. Import it byte for byte as the master (codex-orchestration `references/image-lane.md`).

## Character reference slots

Every cast member has one official reference slot (Matt, 2026-10-12): `wiki/image-library/assets/scenes/comic-b/models/<stem>-v<N>.png`. `<stem>` is the file stem of the sheet registered under the character's `modelRecord` (for example `slop-dedicated`, `model-matt`), or `<character id>-dedicated` for a character with no sheet yet. Each new sheet is saved as the next unused `-vN` in its slot, with provenance in `records/<modelRecord>/<style>/v<N>/`. Earlier versions are never overwritten or moved.

| State | What the cast page shows | What stories and generation use |
|---|---|---|
| Newest `-vN` in the slot is the catalog's current treatment | That sheet, badge "registered · used by stories and generation" | That sheet |
| A newer `-vN` sits in the slot, not yet registered | The newest sheet first, badge "newest · awaiting registration", and the registered version it is waiting to replace | The registered version, until the new one is registered |

Studio reads the slot on each request (`apps/mtw/modules/comics/server/modelVersions.ts`) and lists every version, newest first, with the run's author review (never Matt's approval). Each version shows whether the image catalog holds it (looked up through `/api/images/records`) and carries Approve and Reject buttons that post Matt's decision to `/api/images/decide` (`apps/mtw/modules/comics/client/SlotDecision.tsx`). The Comics module watches the models folder, the `comic-b-model-*` record folders and `wiki/image-library/manifest.json`, so a new sheet on disk and its later registration both refresh `/m/comics/cast` and `/m/comics/cast/<id>` with no reload. The cast page also re-checks the slot every 15 seconds through the media route (`apps/mtw/modules/comics/client/slotProbe.ts`), so a new sheet shows even on a Studio process started before this code. A sheet held in transport (a sealed packet under `.codex/worktrees/`) is not in the slot and does not show, so a character run lands every sheet in its slot as soon as it is generated, whatever other registration is running. Matt's character requests are authoritative over other sessions' leases (Matt, 2026-10-12).

## Selected voices and speech review

Any save to that file, even to another balloon, leaves every approval for that story bound to the old hash: Studio refuses to act on it ("the story changed since the library was built") until the library is rebuilt and the words are re-reviewed, and the Comic Editor shows the issue's approval count as `staleApprovals`. Inserting or deleting a balloon renumbers the later `-bN` ids in that panel. Keying approvals on a stable balloon id is undecided.
